# PaySim dataset

## What it is

PaySim is a **synthetic** mobile-money transaction log. It was generated by a multi-agent
simulator calibrated on one month of real transactions from a mobile-money service in an
African country. The simulator was built by E. A. Lopez-Rojas, A. Elmir and S. Axelsson.
Fraud was injected by agents that take over customer accounts and try to empty them.

- Paper: Lopez-Rojas, Elmir, Axelsson. *PaySim: A financial mobile money simulator for fraud
  detection.* 28th European Modeling and Simulation Symposium (EMSS), 2016.
- Public copy: Kaggle, "Synthetic Financial Datasets For Fraud Detection" (`ealaxi/paysim1`),
  file `PS_20174392719_1491204439457_log.csv` (~470 MB, ~6.36M rows, 744 steps).
- Licence: CC BY-SA 4.0 on Kaggle. **Do not commit the data to this repo.** Credit the
  authors if you publish results.

## Getting it

```bash
pip install kaggle               # needs ~/.kaggle/kaggle.json (Kaggle account -> API token)
kaggle datasets download -d ealaxi/paysim1 -p data/raw --unzip
mv data/raw/PS_20174392719_1491204439457_log.csv data/raw/paysim.csv
```

Or download it in the browser and put the CSV at `data/raw/paysim.csv`. `data/raw/` is git-ignored.

## Schema

| Column | Type | Meaning | Used by the engine? |
|---|---|---|---|
| `step` | int | Simulated hour since start (1 step = 1 hour; 744 = 31 days) | Time ordering, hour-of-day, velocity windows. **Not** a raw model feature |
| `type` | cat | `CASH_IN`, `CASH_OUT`, `DEBIT`, `PAYMENT`, `TRANSFER` | Yes (one-hot) |
| `amount` | float | Amount in local currency | Yes |
| `nameOrig` | str | Originating customer ID (`C…`) | Velocity key only, never a feature value |
| `oldbalanceOrg` | float | Origin balance before | Yes |
| `newbalanceOrig` | float | Origin balance after | Yes (see caveat) |
| `nameDest` | str | Recipient ID; `C…` customer, `M…` merchant | Merchant flag + velocity key |
| `oldbalanceDest` | float | Recipient balance before (blank/0 for merchants) | Yes |
| `newbalanceDest` | float | Recipient balance after | Yes (see caveat) |
| `isFraud` | 0/1 | **Label**: transaction made by a fraudulent agent | Target only. Rejected by the API |
| `isFlaggedFraud` | 0/1 | Output of the simulator's legacy rule (TRANSFER > 200,000) | **Dropped** (leaks a decision) |

## Known characteristics (verify on your copy)

- **Extreme imbalance:** about 0.13% of rows are fraud (~8.2k of ~6.36M). Accuracy is
  meaningless here. Report PR-AUC, and recall at a fixed precision or alert budget.
- **Fraud only appears in `TRANSFER` and `CASH_OUT`.** The fraud pattern is "take over an
  account, transfer the balance to a mule, cash it out".
- **Balance columns are often inconsistent.** Many rows have `oldbalanceOrg - amount !=
  newbalanceOrig`. Many fraudulent transfers show the destination balances as `0 -> 0`.
  These are simulator artefacts, and the "balance error" features exploit them heavily.
  Treat any very high PaySim score as an upper bound. Real ledgers don't behave this way.
- **`isFlaggedFraud` is almost useless.** It fires on a handful of rows and is a rule
  output, not ground truth.
- **Customer IDs rarely repeat as origin.** Origin-side velocity is weak on PaySim.
  Destination-side (mule) velocity carries more signal.
- **Merchants have no destination balance information.**

## How this repo uses it

1. `fraud_engine.preprocessing.load_paysim` loads the CSV with explicit dtypes and validates
   the schema: columns, types, no negative money, no missing labels.
2. `build_feature_frame` replays the rows in `step` order through the same feature code
   and velocity store as the API.
3. `temporal_split` makes a time-based train / gap / test split.
4. `fraud_engine.train` fits the logistic baseline, reports model vs rules-only metrics,
   and writes `models/baseline.json` + `models/baseline.metrics.json`.

For quick experiments use `--nrows` (for example 500k). Steps are in order in the file,
so a prefix is a valid earlier time window.

## Synthetic stand-in for CI

`fraud_engine.synthetic` produces a small CSV in the same schema so CI can run the whole
pipeline without the real file. It's deliberately easy, so a perfect score on it means
nothing. Use it to test plumbing, never to judge model quality.
